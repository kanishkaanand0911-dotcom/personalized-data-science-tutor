System architecture & pitch reference

An agent that shows its work, teaching the work it shows.

VYBE Learn is a gamified data-science tutor built around one real constraint: a deterministic agent cleans data and selects a model on its own — observe, decide, act, evaluate, adapt — and the learner's job is to predict what it will do, not steer it. An LLM narrates and tutors on top; it never makes the analytical decisions.

02 — The actual agent

Observe → decide → act → evaluate → adapt

The same five-step loop runs twice: once choosing a cleaning strategy per column, once choosing a regression model. Each escalation is justified by a specific measured failure — not "try everything, keep the best score."

01

Observe

Column stats, skew, null%, dtype — or dataset shape, feature count, linearity signal.

02

Decide

Pick the simplest candidate strategy first, with a stated reason.

03

Act

Apply the transform, or fit the model.

04

Evaluate

Re-measure: skew shift, cross-validated R²/RMSE, residual pattern.

05

Adapt

Pass → keep. Fail → escalate to the next candidate and repeat.

skew shift ≤ 15% → cleaning fix kept R² ≥ 0.15 → model acceptable |residual↔prediction corr| ≤ 0.25 → no missed pattern
Issue typeCandidate ladder (simplest first)
Missing numericimpute_median → impute_knn
Missing categoricalimpute_mode
Inconsistent labelsnormalize_categories (fuzzy match)
Numbers stored as textcoerce_numeric_strings
Mixed-up date formatscoerce_dates
Model familyLinearRegression → Ridge → RandomForest → GradientBoosting
03 — Never a dead end

Three tutor tiers, one honest fallback

Every chat and mentor reply tries the richest source first and degrades gracefully — each tier returns nothing rather than a guess, so a missing key or a second server never breaks the chat, it just quietly narrows what's available. The UI always discloses which tier actually answered.

04 — Built this session

AI Mentor: platform-wide, mode-aware coaching

A floating panel available from any screen, fed a live context object instead of just the last message — and instructed to nudge, not solve, until the learner has actually tried.

Guided

Struggling

Very simple language, one step at a time, concrete example, one question per reply.

Assisted

Making progress

Names the concept, gives a partial hint, asks for another attempt before revealing more.

Independent

Confident

Minimal hints — asks the learner to justify their own reasoning and code.

05 — Learning path

Six stages, ten real steps

Verification sits as a bridging step between Cleaning and EDA — real, tested functionality, not one of the six named stages, kept because it's the honest answer to "did the fix actually work?"

01

Python & Data Fundamentals

Read a CSV, understand rows/columns, real pd.read_csv / df.shape / df.columns.

02

Data Cleaning

One level per detected issue — missing values, inconsistent labels, bad dates, numbers-as-text.

4 issues on the sample dataset⏭ "Skip cleaning" → jumps straight to Verification
—

Verification (bridge)

Runs real downstream tasks on the cleaned data — aggregation, a bar chart, a trend line.

03

Exploratory Data Analysis

Real histograms, category bars, monthly trend — plus a correlation card grounded in the model's own observation.

04

Machine Learning Foundations

Target, features, train/test split, regression vs. classification — all named from the real dataset.

05

Model Selection & Evaluation

The second agentic loop, narrated: why this model, what it explained, why it was kept.

⏭ "Skip modeling" → jumps straight to Final Project
06

Final Project

Full recap — every cleaning decision, every chart, the chosen model, portfolio-ready.

⏭

Skip the basics — on purpose

Cleaning and Modeling both carry an explicit "Skip" action in the study top bar. A confident learner isn't forced through busywork to reach the part they actually came for — they jump straight to Verification or Final Project, and the Rail sidebar marks those steps honestly incomplete rather than faking a checkmark. The same respect-for-mastery idea behind the Mentor's Independent mode, expressed as real navigation, not just tone.

08 — For the deck

What to actually say

The hook

  • The agent cleans data and picks a model completely on its own — the learner predicts, never steers.
  • Every "why" on screen is a real measured number, not a canned explanation.
  • Wrong guesses cost points but never touch the data — guesses are scored alongside the agent, never fed into it.

The differentiator

  • Two real agentic loops (cleaning, modeling) — same observe/decide/act/evaluate/adapt shape, reused on purpose.
  • A mentor that refuses to just answer — three modes tuned to how stuck the learner actually is.
  • The tutor layer can vanish entirely (no key, no ADK server) and the product still teaches, honestly.

Live demo order

  • Load the sample dataset → show the 10-step roadmap.
  • Guess a cleaning strategy wrong → reveal the agent's real backtrack (median discarded, KNN kept).
  • Open the AI Mentor mid-lesson → switch modes → ask "give me a hint."
  • Jump to Model Selection → show the escalation reasoning → Final Project recap.

If asked "where's the AI"

  • Two places, on purpose: the deterministic core (decisions) and the narration layer (explanation) — never the same code path.
  • That separation is why a judge can trust the R² on screen — no LLM ever touched the math.
